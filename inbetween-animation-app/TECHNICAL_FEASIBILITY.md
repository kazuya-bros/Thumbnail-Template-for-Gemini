# 中割りアニメーション自動生成アプリ - 技術要件・実現可能性分析

## 概要

2枚のキーフレーム画像（目開き口閉じ / 目閉じ口開き）から、任意の比率（1/4, 1/2, 3/4等）で中割り画像を自動生成し、滑らかな口パク・瞬きアニメーションを作成するWindowsデスクトップアプリ。

---

## 技術スタック候補

### フロントエンド / デスクトップフレームワーク

| 技術 | バイナリサイズ | メモリ使用量 | 備考 |
|------|-------------|------------|------|
| **Tauri 2.0** | ~3MB | ~30MB | Rust製、WebView2利用。軽量だがPython連携に工夫が必要 |
| Electron | ~80-120MB | ~150MB+ | 重い。今回の用途にはオーバースペック |

**結論: Tauri 2.0 を採用**

---

## コア技術の分析

### 1. 顔パーツのセグメンテーション（目・口の領域特定）

#### 選択肢A: dlib 68点ランドマーク検出（推奨）
- **実現性: ◎**
- 目: points [36-47], 口: points [48-67] で正確に特定可能
- 軽量（CPU推論で十分、リアルタイム処理可能）
- Python `dlib` パッケージで簡単に利用可能
- イラスト/アニメ顔には精度が落ちる可能性あり

#### 選択肢B: MediaPipe Face Mesh（468点）
- **実現性: ◎**
- より高密度なランドマーク（468点）
- Google製、クロスプラットフォーム対応
- dlib より高精度だが、やや重い

#### 選択肢C: SAM 3（Segment Anything Model 3）
- **実現性: △**
- 848Mパラメータ → 「軽量アプリ」との矛盾
- モデルサイズ: 数GB（ダウンロード・ディスク容量）
- GPU推奨（CPUだと非常に遅い）
- テキストプロンプト「eye」「mouth」で概念ベースのセグメンテーションが可能
- **オーバースペック**: 顔パーツの検出にはランドマーク検出で十分

### 2. 中割り画像の生成（最重要）

#### 選択肢A: OpenCV + dlib による従来型フェイスモーフィング（推奨）
- **実現性: ◎**
- パイプライン:
  1. 両画像の68点ランドマーク検出
  2. Delaunay三角形分割
  3. アフィン変換によるワーピング
  4. アルファブレンディング（α = 0.0〜1.0の任意値）
- **任意の比率サポート**: α値を変えるだけ（0.25, 0.5, 0.75...）
- **メリット**: 完全ローカル処理、決定的な結果、高速（<1秒/枚）
- **デメリット**: 大きな形状変化（目の開閉）では artifacts が出やすい

#### 選択肢B: Nano Banana（Gemini 2.5 Flash Image）API
- **実現性: ○**
- Google Gemini API経由でアクセス（モデルID: `gemini-2.5-flash-image-preview`）
- キャラクター一貫性の維持が得意
- プロンプトで「目を半分開いた状態」等の指示が可能
- **コスト**: ~$0.039/画像（~1,290トークン/枚）
- **メリット**: セマンティックな理解（「半開きの目」の概念を理解）
- **デメリット**: API依存（オフライン不可）、レイテンシ、非決定的

#### 選択肢C: RIFE（Real-Time Intermediate Flow Estimation）
- **実現性: ○**
- 2枚の画像間のフレーム補間に特化したニューラルネット
- 任意のタイムステップ（0.0〜1.0）で補間可能
- ncnn/Vulkan版あり（AMD/Intel GPUでも動作）
- **メリット**: 高品質な補間、ローカル処理可能
- **デメリット**: モデルサイズ ~50MB、GPU推奨

### 3. パーツ別処理（重要な差別化ポイント）

目と口を**独立して**制御する必要がある（目は開→閉、口は閉→開が同時に必要）。

#### 推奨アプローチ: マスクベース合成
1. ランドマーク検出で目・口の領域マスクを生成
2. 目の領域と口の領域を**別々の比率で**モーフィング
3. 元画像の顔全体にマスク合成（Poisson Blending or Alpha Blending）

これにより:
- 目の開閉: α=0.0（全開）→ α=1.0（全閉）
- 口の開閉: α=0.0（全閉）→ α=1.0（全開）
- **独立制御**が可能

### Python Sidecarのバンドル方式

| 方式 | サイズ | 備考 |
|------|-------|------|
| **PyInstaller** | ~100-200MB | Python + 依存を1バイナリに。配布が簡単 |
| **Embedded Python** | ~50-100MB | tauri-plugin-python で組み込み |
| **System Python** | 0MB | ユーザーにPython環境を要求。UXが悪い |

## リスクと制約

### 技術的リスク
1. **イラスト顔の対応**: dlib/MediaPipeは実写顔に最適化されている。アニメ・イラスト顔ではランドマーク検出精度が大幅に低下する可能性がある
2. **目の開閉モーフィング品質**: 目を閉じる動作は形状変化が大きく、単純なワーピングでは不自然になりやすい
3. **Python Sidecarのサイズ**: PyInstaller化すると100MB以上になり「軽量」とは言い難い

### 対策案
1. → イラスト顔には Anime Face Landmark Detection（例: `face_alignment` ライブラリ）やカスタムモデルを検討
2. → RIFEやNano Bananaとの併用で品質向上。または目の領域のみ複数枚のテンプレート画像を用意する
3. → ONNX Runtime + Rust直接実装でPython依存を排除する将来的な最適化パス

## 入力画像の要件

- 同一キャラクター/人物の2枚
- 画像A: 目が開いていて口が閉じている
- 画像B: 目が閉じていて口が開いている
- 推奨: 同一ポーズ、同一背景、同一ライティング
- フォーマット: PNG/JPEG
- 解像度: 512x512 以上推奨

---

## 出力

- 指定比率（1/4, 1/2, 3/4 等）の中割り画像群
- アニメーションGIF/APNG/連番PNG
- 将来的: MP4動画出力
